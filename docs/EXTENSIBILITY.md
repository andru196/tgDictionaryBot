# Расширяемость

Как добавить новый вид записей, не трогая существующий код.

Сегодня видов четыре — еда, симптомы, идеи, вопросы. Завтра захочется сна, лекарств, тренировок, веса, настроения, трат. Если каждый новый вид требует правки сегментатора, миграции БД, ветки в отчёте и нового `if` в трёх местах — расширение остановится на шестом. Поэтому вид записей оформлен как **модуль**: вертикальный срез, который сам приносит всё, что ему нужно.

---

## 1. Что такое модуль

```csharp
public interface IDiaryModule
{
    string Key { get; }                                   // "gi", "notes", "sleep"

    /// Категории, которые модуль умеет извлекать.
    /// Из них СОБИРАЕТСЯ промпт сегментации — редактировать его руками не нужно.
    IReadOnlyList<CategoryDescriptor> Categories { get; }

    /// Экстракторы, проекции, аналитика, всё внутреннее хозяйство модуля.
    void ConfigureServices(IServiceCollection services, IConfiguration config);

    /// Секция отчёта и её место в документе. null — модуль не рисует ничего.
    IReportSectionProvider? ReportSection { get; }

    /// Собственные подкоманды: diary stats gi …, diary sleep debt …
    IEnumerable<Command> CliCommands { get; }
}

public sealed record CategoryDescriptor(
    CategoryKey Key,              // "meal", "symptom", "sleep"
    string Title,                 // «Приём пищи»
    string WhenToUse,             // «человек говорит, что он съел или выпил»
    IReadOnlyList<string> Examples,   // 3–5 реальных фраз
    Type PayloadType,             // из него генерируется JSON-схема
    string[] Hashtags);           // #еда — детерминированный обход LLM
```

Ядро при старте собирает все зарегистрированные модули в `IModuleRegistry` и дальше работает только с ним. Про существование ЖКТ или заметок оно не знает.

## 2. Три места, где реестр отрабатывает автоматически

Это и есть разница между «расширяемо» и «расширяемо на словах».

### Промпт сегментации собирается из реестра

Сегментатору не прописан список категорий — он строит его из `CategoryDescriptor`:

```
Раздели сообщение на смысловые фрагменты. Для каждого укажи категорию:

- meal — приём пищи. Когда: человек говорит, что он съел или выпил.
  Примеры: «поужинал жарёхой», «выпил кофе натощак»
- symptom — симптом ЖКТ. Когда: человек описывает самочувствие …
- sleep — сон.  ← появилось само, как только модуль зарегистрирован
  …
```

Enum категорий в JSON-схеме сегментации генерируется оттуда же. Новый модуль → сегментатор немедленно знает про новую категорию, и ни один существующий файл не отредактирован.

### Хранение не требует миграции

`entries` хранит общие поля колонками, специфику — в `payload` (JSON). Новый вид записей ложится туда без изменения схемы.

Миграция нужна, только если модулю нужны **проекции** — денормализованные таблицы под собственную статистику. Правило простое:

> Проекция нужна, когда по этим данным будут гоняться агрегаты за произвольные периоды и объём растёт линейно со временем.

ЖКТ проекции завёл (`gi_meal_items`, `gi_symptoms`) — иначе «статистика за год» стала бы полным сканом с разбором JSON. Модулю «идеи» проекции не нужны: их читают целиком за период и их мало. Модуль решает это сам, реализуя `IEntryProjector` или не реализуя его.

### Отчёт собирается из секций

Ядро рендерит документ, спрашивая у реестра секции и сортируя по `Order`. Ветвлений по типу модуля в шаблоне нет.

## 3. Рецепт: добавить модуль «Сон»

Полная последовательность. Ни один существующий файл не редактируется, кроме одной строки регистрации.

**1. Проект `src/Diary.Modules.Sleep/`.** Ссылается на `Diary.Domain` и `Diary.Application` — и всё. На инфраструктуру ссылаться нельзя: модуль работает через порты.

**2. Payload — контракт извлечения.**

```csharp
public sealed record SleepPayload(
    TimeOnly? BedTime,
    TimeOnly? WakeTime,
    double? Hours,
    SleepQuality Quality,          // Poor | Fair | Good
    IReadOnlyList<string> Disruptions);   // «просыпался», «духота», «изжога»
```

Из типа генерируется JSON-схема для structured output. Контракт один, разъехаться ему не с чем.

**3. Дескриптор категории.**

```csharp
new CategoryDescriptor(
    Key: "sleep",
    Title: "Сон",
    WhenToUse: "человек рассказывает, как спал: во сколько лёг, сколько проспал, просыпался ли",
    Examples: ["лёг в час, встал в семь, разбитый", "спал нормально, часов восемь", "полночи не мог уснуть"],
    PayloadType: typeof(SleepPayload),
    Hashtags: ["#сон"])
```

**4. Промпт `Prompts/extract-sleep.v1.ru.md`** — embedded resource, узкий, только про сон.

**5. Экстрактор.**

```csharp
internal sealed class SleepExtractor(IStructuredCompletion llm) : IEntryExtractor
{
    public CategoryKey Category => "sleep";

    public async Task<DiaryEntry> ExtractAsync(EntryFragment f, ExtractionContext ctx, CancellationToken ct)
    {
        var payload = await llm.CompleteAsync<SleepPayload>(
            Prompts.ExtractSleep, f.Text, LlmRole.Extraction, ct);
        return DiaryEntry.Create(f, "sleep", "sleep", payload, ctx);
    }
}
```

**6. Секция отчёта** — Razor-компонент + `IReportSectionProvider` с `Order`. Или ничего, если сон нужен только в статистике.

**7. Регистрация — единственная правка вне модуля:**

```csharp
services.AddDiaryModule<SleepModule>();
```

Готово. Сегментатор знает про сон, записи сохраняются, отчёт получил секцию, а `diary reprocess --since …` переразберёт всю накопленную историю и достанет оттуда сон, про который раньше никто не спрашивал. **Это работает задним числом, потому что сырьё и транскрипты хранятся отдельно от интерпретации.**

## 4. Модули, которые связаны друг с другом

Сон и ЖКТ хочется сопоставить: «после плохого сна изжога чаще». Прямая ссылка `Modules.Gi → Modules.Sleep` убьёт независимость, поэтому связь идёт через ядро.

Модули публикуют **сигналы** — временные ряды в общем формате:

```csharp
public interface ISignalProvider
{
    IReadOnlyList<SignalDescriptor> Signals { get; }   // "sleep.hours", "sleep.quality", "gi.severity"
    Task<IReadOnlyList<SignalPoint>> GetAsync(SignalKey key, DateRange period, CancellationToken ct);
}
public readonly record struct SignalPoint(DateTimeOffset At, double Value);
```

Кросс-модульный анализ живёт в ядре и работает с абстрактными рядами: он не знает, что такое сон, — он видит два ряда и считает лаговую корреляцию. Новый модуль, опубликовавший свой сигнал, автоматически попадает в общую матрицу сопоставлений.

Оговорка, которую надо помнить: чем больше сигналов, тем больше пар, и тем выше шанс случайных совпадений. Кросс-модульные находки показываются с более строгим порогом и явной пометкой, что это гипотеза, а не вывод.

## 5. Что расширяется помимо видов записей

Точки, спроектированные как сменные, — потому что в каждой из них выбор со временем поменяется:

| Точка | Порт | Зачем менять |
|---|---|---|
| Источник сообщений | `IMessageSource` | MTProto сегодня, что-то ещё завтра; в тестах — фейк |
| Понимание речи | `IUtteranceReader` | Whisper → нативное аудио → гибрид ([MODELS.md](MODELS.md)) |
| Модель под шаг | `IChatClientFactory.For(role)` | разные модели на сегментацию и извлечение |
| Политика хранения | `IRetentionPolicy` | Keep / React / Delete и любая своя |
| Формат вывода | `IReportRenderer`, `IStatsFormatter` | HTML, JSON, CSV, Markdown в Obsidian |
| Окна экспозиции | `IExposureWindowPolicy` | табличные, откалиброванные, ручные |

## 6. Границы, которые нельзя переходить

Расширяемость держится ровно до тех пор, пока соблюдаются четыре правила:

1. **Модуль не ссылается на инфраструктуру.** Только `Domain` + порты `Application`. Иначе тесты модуля потянут за собой SQLite и HTTP.
2. **Модуль не ссылается на другой модуль.** Связь только через сигналы (раздел 4).
3. **Ядро не знает про конкретные модули.** Появился `if (moduleKey == "gi")` в ядре — расширяемость кончилась, чини сейчас.
4. **LLM в модуле только извлекает.** Считает — детерминированный код модуля. Иначе статистика перестаёт быть воспроизводимой и тестируемой.
5. **Модуль не знает про субъектов.** Он получает уже настроенный на нужного человека `DbContext` и пути — ни один его метод не принимает `SubjectId`, поэтому подставить чужой невозможно ([MULTI-SUBJECT.md](MULTI-SUBJECT.md), раздел 2). Побочный эффект приятный: модуль пишется так, будто пользователь один.

Набор модулей задаётся **на каждого субъекта отдельно** (`Modules: ["gi"]`). Это сужает не только отчёт, но и промпт сегментации: сегментатор не должен искать идеи там, где их не ведут, иначе будет находить их в описании обеда.
