# tgDictionaryBot

Личный голосовой дневник в Telegram, который разбирается локальной LLM и превращается в один красивый HTML-файл.

Наговариваешь в свой приватный канал что попало — что съел, что заболело, какая мысль пришла, что надо загуглить. Потом запускаешь анализ: локальный Whisper расшифровывает голосовые, локальная модель в LM Studio раскладывает речь по категориям, детерминированный код считает корреляции «еда → симптом» за любой период, и на выходе получается отчёт.

**Ничего не уходит наружу.** LLM локальная, распознавание локальное, база локальная. Единственное соединение с интернетом — за собственными сообщениями в Telegram.

## Четыре решения, на которых держится остальное

**MTProto, а не бот.** Bot API хранит непрочитанные апдейты 24 часа — с ним «включу раз в год» было невозможно. Личный аккаунт читает всю историю и качает медиа любой давности, так что always-on демон не нужен: всё живёт в одном консольном приложении, которое запускается когда захочется.

**LLM только извлекает структуру, считает обычный код.** Локальная модель невоспроизводима между запусками и плохо считает. Корреляции, окна экспозиции и точный тест Фишера живут в детерминированном коде и покрыты unit-тестами — статистика обязана быть одинаковой при повторном прогоне.

**Сырьё отдельно от интерпретации.** Сообщения и транскрипты хранятся навсегда, рядом с каждой извлечённой записью пишется модель и версия промпта. Вышла модель получше — `diary reprocess`, и вся история разобралась заново. Накопленные данные не устаревают вместе с моделью.

**Субъект — это скоуп, а не параметр.** Людей может быть несколько, у каждого своя база и свои настройки. Забытый `WHERE SubjectId = …` — баг, который не падает и выглядит как правдоподобные цифры, поэтому колонки `SubjectId` просто нет: у каждого свой файл БД. Маршрутизация — по id отправителя, неопознанные уходят в карантин.
